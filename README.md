# Python for reading code and Linux administration

Learn to read Python, review AI-assisted code, and explain what a script will do before running it. Then use Python to turn RHEL service-command results into a clear server report.

**[Start here](START-HERE.md)** is the only page you need to begin. It links to setup and one lesson per day. No previous coding experience or AI account is required.

| Day | Main question |
| --- | --- |
| 1 | What do these variables, types, and decisions mean? Why does Python matter for server work? |
| 2 | What repeats in a for or while loop, and what makes it stop? |
| 3 | What do imports do, and how does Python run a RHEL command? |
| 4 | Can I find mistakes, test an AI suggestion, and remove unnecessary work? |
| 5 | Can another person run my reviewed script, and can I explain my approval decision? |

You start with a **working ServerBrief script**, not an empty file. Your final portfolio contains a reviewed script, an annotated explanation, test evidence, and a short server-status report. You will still make small code changes: enough to verify that you understand the behavior and can repair a defect.

The core lessons use fictional saved command results on Windows, macOS, or Linux. The RHEL lab adds real, read-only commands on an instructor-assigned RHEL 9 or compatible VM. Sample mode is explicitly labeled simulated. It does not pretend to inspect a server.

The numbered folders follow the program's submission requirements. You do not need to navigate them in order. Follow Start Here instead. Instructor guides and answer keys remain in a separate private repository.

Five days, each with 180 minutes guided learning and 180 minutes project work. Breaks and lunch are additional. Materials are prepared for instructor review. Classroom pacing and live RHEL behavior still require testing on the assigned VM image.
